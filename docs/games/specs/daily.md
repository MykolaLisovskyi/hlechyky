# Щоденний глек (`daily`) — пункт 84

Не окрема гра, а каркас навколо щоденних соло-головоломок. Сервісна частина — WP1 (`Economy/Daily.cs`),
панель — WP2 (`core.js`), а G-wordle доводить обидві до ладу на реальних іграх (перша — Глек-слово, друга —
Сапер дня від G-mines).

## Сервіс `Daily` (WP1)

Час, сід і номер дня вже є в контракті — статичний `Days` у `Contracts.cs` (`Days.Today(clock)`,
`Days.Seed(puzzleId, day)`, `Days.NextMidnight(now)`, `Days.Number(day)`), маркер `IDailyGame` — там само.
`Daily` — тонкий сервіс над ними:

```csharp
public sealed class Daily(IClock clock)
{
    public string Today() => Days.Today(clock);
    public IReadOnlyList<string> Puzzles;           // Id ігор, що реалізують IDailyGame (свій скан збірки, щоб не залежати від Registry WP0)
    public DailyStatus Status(string nick);         // те, що віддає GET /api/games/daily
}
```

Таблиця `daily_results(day, game, nick_key, nick, solved INTEGER, attempts INTEGER, ms INTEGER, created_at, PRIMARY KEY(day, game, nick_key))` —
пишеться з `SoloScoreEvent`, де `Key` = `daily:<game>:<day>:<nick_key>` (гра передає ключ кімнати). Серія
(streak) = кількість послідовних днів до сьогодні з `solved=1` для гри.

HTTP `GET /api/games/daily` →
```ts
{ day, no, nextMidnight,
  puzzles: [{ game, title, me: { solved, attempts, ms } | null, streak, solvedCount,
              top: [{ nick, attempts, ms }] (≤ 10, за attempts↑ потім ms↑) }] }
```

## Панель (WP2)

У вкладці «Ігри» — окрема кнопка/вкладка «Щоденний глек»: картки кожної щоденної гри (назва, «розв'язано
за N спроб / не розв'язано», серія 🔥N, «N людей уже розв'язали»), кнопка «Грати» → `OpenSolo(game)` →
кімната відкривається на тій же вкладці (соло-кімнати малюються так само, як звичайні, але без чіпів місць
і без «Дивлюсь збоку»). Топ-10 дня під карткою.

## Нагорода

`DailyReward=5` черепків за розв'язану головоломку (гра кличе `Award` з `reason "daily:<game>"`, стеля — раз
на день через ref). Ачівки `wordle-2`, `wordle-7`, `mines-fast` — WP1 за `SoloScoreEvent`.

## Тести (WP1: ≥ 8; G-wordle: інтеграція)

- `Today()` на 20:59 UTC 09.09 → «2026-09-09»; на 21:01 UTC → «2026-09-10» (Київ = UTC+3 у вересні).
- `Seed` стабільний і різний для різних puzzleId/днів.
- Streak: 3 дні поспіль → 3; пропуск учора → 0 (або 1, якщо сьогодні розв'язано).
- `daily_results` upsert не дублює; топ сортується за спробами, потім часом.

## Як реалізовано (WP1)

`Economy/Daily.cs` — сервіс, `Economy/Store.cs` — таблиця `daily_results`, `Economy/Rewards.cs` — міст від
подій каркаса. HTTP `GET /api/games/daily` віддає `DailyStatus` рівно тієї форми, що вище; `puzzles`
береться зі свого скану збірки за маркером `IDailyGame` (`GameNames.Daily`), тож панель порожня, поки
щоденних ігор нема, і заповнюється сама, щойно перша з'явиться.

Дві домовленості, яких у контракті бракує, і які варто знати авторам щоденних ігор:

- **Одне число замість двох.** `SoloScoreEvent` несе лише `Score`, а `daily_results` тримає і `attempts`,
  і `ms`. Тому: `Score < 1000` — це спроби (`attempts = Score`, `ms = 0`), `Score >= 1000` — мілісекунди
  (`ms = Score`, `attempts = 1`). Жодна головоломка не потребує тисячі спроб і жодна не розв'язується за
  секунду, тож межа безпечна. Гра, якій треба записати обидва числа, кличе `Ctx.Score(seat, ms, attempts)`:
  тоді `SoloScoreEvent.Attempts` задано, `Score` — мілісекунди, і вгадування не буде (так робить Сапер дня).
  Незакритий день (`solved = 0`) пишуть через `Daily` з `Ctx.Services`:
  `Record(game, nick, solved, attempts, ms, day = null)`.
- **Ключ кімнати.** Ключ має бути `daily:<game>:<day>:<nick_key>` — саме з нього беруться гра і день;
  `<day>` перевіряється як `рррр-мм-дд`. Ключ іншої форми (або з «днем», якого не буває) запишеться як
  звичайний соло-результат, у лог піде попередження, а в панель «Щоденного глека» він не потрапить.

Нагорода: гра кличе `Ctx.Award(seat, shards, "daily:<game>")`, а WP1 підставляє ref
`daily:<game>:<day>:<nick_key>` — раз на день на головоломку, як і сказано вище. `shards = 0` для причини
`daily:` означає «плати типову» — береться `Economy:DailyReward` із налаштувань. Ачівки `wordle-2`,
`wordle-7` і `mines-fast` рахуються з `daily_results` одразу після запису результату.

Соло-таблиці (гончарне коло, сапер, найкраща реакція в дуелі) тримають один рядок на ключ кімнати **і
день**: `room_id` соло-результату — це `<ключ>:<день>`. Інакше «найкращий результат за сьогодні» показував
би рекорд місячної давнини, бо рядок був би один на все життя. Найкраще за весь час (`BestSolo`, ачівки
гончаря) при цьому не змінилось: воно рахується по всіх рядках.

Серія: `Daily.Streak(nick, game)` іде від сьогодні назад по днях із `solved = 1`. Якщо сьогодні ще не
грали, відлік починається від учора — інакше серія «падала» б щоранку до першої партії.

## Як реалізовано (G-wordle: перевірка на живій головоломці)

Глек-слово — перша справжня щоденна гра, і весь ланцюг зійшовся без жодної правки каркаса. Що саме
перевірено на сервері зі свого worktree (порт 8115, 9 вересня 2026):

- **Каталог.** Досить оголосити клас із маркером `IDailyGame` — `Registry.Describe` ставить `daily: true`,
  `GameNames(Registry)` бере звідти `Puzzles`, і гра з'являється в `GET /api/games/daily` та в панелі
  «Щоденний глек» сама. Вписувати її кудись ще не треба.
- **Ключ.** `SoloKey(nickKey, clock)` → `daily:wordle:<рррр-мм-дд>:<нік>`; `Rooms.OpenSolo` кладе його в
  `Room.Key`, `Ctx.Score` несе його в `SoloScoreEvent.Key`, `Rewards.Solo` розбирає на гру й день.
  Працює рівно так, як описано вище.
- **Одне число.** Глек-слово віддає `Ctx.Score(0, спроби)` (2 ≪ 1000), і в `daily_results` лягає
  `attempts = 2, ms = 0`. Незакритий день гра не пише взагалі — інакше рядок був би `solved = 1`.
- **Нагорода.** `Ctx.Award(0, 0, "daily:wordle")`: нуль означає «типова щоденна» — у гаманці +5, ref за
  днем, повторне відкриття кімнати вдруге не платить.
- **Ачівки.** `wordle-2` видалась одразу після запису результату («З двох спроб», +20), у Журналі —
  рядок про неї. Серія 🔥1 і топ дня в панелі з'явились після першого ж розв'язання.

Два застереження для авторів наступних щоденних ігор.

**Ключ кімнати зараз називає клієнт — і це підробка дня.** `RadioHub.OpenSolo(gameId, key)` пропускає
рядок клієнта в `Rooms.OpenSolo`, а той бере його як є, коли він не порожній. Гра грає сьогоднішню
головоломку (день вона бере з `Ctx.Clock`), а `Rewards.Solo` дістає гру й день **із ключа** — тож
`OpenSolo('wordle', 'daily:wordle:2026-09-03:оля')` запише розв'язання за 3 вересня, намалює серію й
видасть ачівку за серію. Гра захиститись не може: ключа своєї кімнати вона не бачить. Правильне місце
лікування — `Rooms.OpenSolo` (для `IDailyGame` складати ключ самому або звіряти з `SoloKey`) і, як друга
страховка, `Rewards.Solo` (звіряти `parts[1]` з `e.GameId`, відкидати день із майбутнього). Поки цього
нема — оголошуйте це в «Потрібно від каркаса» свого spec, а на цифри в панелі щоденного дивіться як на
такі, що людина може собі домалювати.

**Картка панелі не оновлюється сама.**
`renderDaily` малюється лише при перемиканні панелі (`chromeFor !== panel` у `core.js`), тож одразу
після розв'язання картка ще каже «ще не розв'язано» — треба вийти в іншу панель і повернутись. Кімната
при цьому оновлюється нормально, бо йде подією `room`.
