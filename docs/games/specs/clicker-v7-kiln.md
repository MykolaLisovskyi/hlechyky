# Гончарне коло v7 — B2 «Горно й розпис»: як реалізовано

Контракт — `clicker-v7.md` §2.7 і §4 B2. Код: `src/Hlechyky/Games/Impl/ClickerKiln.cs` (партія `Clicker` + статичні
`KilnHeat` і `KilnPaint`), клієнт `web/games/clicker-kiln.js/.css`, тести `tests/Hlechyky.Tests/Games/ClickerKilnTests.cs`.
Спільних файлів пакет не чіпав.

Цикл: **виліпив → висохло → горно → комора**. Горно бере лише сухі сирці (`TakeDry`), кожен цілий обпалений виріб
іде в `PutItems` і в `AddFired` (альбом, цех, майстерність). Тріснуті в комору не йдуть і в `AddFired` не рахуються
(тріснутий — не «обпалений виріб» для альбому); за них — черепки на засипку: 15 % ціни простого звичайного.

## Горно

| | |
|---|---|
| Місць | `min(24, 6 + Level("kiln") / 10) + KilnSlotsBonus` (`internal int KilnSlotsBonus { get; set; }` — ставить цех, типово 0) |
| Стани (`kiln.state`) | `cold` → `loaded` (`load`) → `burning` (`light`) → `cooling` (відкрито, 60 с) → `cold`/`loaded` |
| Обпал | 30 с (300 кроків по 100 мс) |
| Холоне | 60 с від відкриття; **складати й розписувати можна й під час охолодження**, розпалити — ні |
| Покинуте ручне горно | через 15 хв після кінця відкриває підмайстер (якість 1, без тріщин) — нічого не губиться |
| Престиж «Обпал» | партія в горні (і та, що палає), солома й недомальований розпис згорають; остання подія стирається |

Дія одна — `kiln { op, … }`:

- `load { n? }` — сухі з сушарні, скільки влізе (або n). Відмови: палає / повне / мокрі / сушарня порожня.
- `light { helper?, straw? }` — порожнє горно саме бере сухі. `helper: true` — підмайстер-палій: без мінігри, **якість 1,
  без тріщин**, Око майстра не рахує, горно відкривається саме (в `Sync`) рівно через 30 с; клієнт після цього просить `look`.
  `straw: true` — одна в'язка соломи на партію (лише для ручного обпалу).
- `open { t: [[мс, дія], …] }` — лише ручний обпал. Мітки — від розпалу, **строго зростають**, `0 ≤ мс < 30000`, дія
  `0` поліно / `1` відкрити заслінку / `2` прикрити, не більше **80**. Від `light` мусить минути ≥ 30 с − 0,5 с (пінг).
  Далі `GuardGate(now)`: майстер хоче глянути — горно лишається палати (таймлайн клієнт тримає в localStorage і пришле
  знову). Сервер сам проганяє `KilnHeat.Run(seed, t)`, кидає тріщини й якість із `Ctx.Rng`, `GuardSpend(120)`.
- `paint { style, tech? }` — розпис партії з колекції (`""` — простий). Без `tech` — лише розпис (краса 0). З `tech` —
  новий візерунок (зерно в збереженні, у вид — лише форма), попередня краса скидається. Живе 5 хв.
- `decor { path: [dt, x, y, …] }` — траєкторія мінігри → краса 0–100 (див. нижче). Візерунок після здачі згорає.
- `straw { n }` — в'язки соломи, ціна кожної — **2 ціни простого звичайного горщика** (`ItemValue("pot","",1)`,
  на голому колі 40 глеків), у клуні до 20.

Ачівка `potter-kiln-perfect` — ручний обпал, ≥ 4 вироби, усі дзвінкі.

## Модель жару (однакова на C# і JS)

Детермінована, крок 100 мс, лише `+ − × ÷ min max` над double (exp/pow/sin могли б розійтись між .NET і V8 в останньому
знаку). Пориви вітру й розміри полін — xorshift32 на цілих із `kiln.seed` (у виді лише під час ручного обпалу).

```
Стан: T = 20 °C, F = 1,0 (розпалка), заслінка відкрита.
Дії кроку i (усі з мс/100 ≤ i):  поліно: якщо F < 2,6 → F = min(2,6; F + 0,4 × розмір/100), T = max(20; T − 15)
                                 відкрити/прикрити заслінку.
F −= F × Burn × 0,1                Burn:  відкрита 0,12   прикрита 0,045
T += (F × Heat − (T − 20) × Loss × (порив ? 2 : 1)) × 0,1
                                   Heat:  відкрита 240    прикрита 60
                                   Loss:  відкрита 0,21   прикрита 0,12
Смуга: n = i + 1; поки n < 80 (8 с розігріву) — лише стеля 350 + 660·n/80; далі 830…1010 °C.
Перегрів: over += (T − стеля) × 0,1, якщо T вище стелі (градусо-секунди).
Рахунок (після розігріву): у смузі 1; до 100° нижче — лінійно до 0; до 60° вище — лінійно до 0.
H = сума / 221.
Пориви: перший на 4–7 с, далі кожні 5,5–11 с, тривають 1,5–3 с. Поліна: 60–140 % (по одному на кожне підкинуте).
```

Сенс: відкрита заслінка — рівновага ≈ 1140·F, дрова горять швидко; прикрита душить вогонь (≈ 500·F) і береже дрова —
так збивають перегрів або тримають жар повною топкою. Переклав дров — жар вилітає за стелю, і збити його можна лише
заслінкою. Порив вітру на 2 с остуджує — хто кидається підкидати, той потім перегріває.

Ризик тріщини виробу: `clamp((over − 300) / 3000; 0; 0,5)`, із соломою ×0,25.

Контрольний вектор (тест `The_heat_model_gives_the_reference_numbers_the_client_repeats`): зерно 12345, дії
`[300,0] [900,0] [4000,0] [7200,2] [9100,0] [12000,1] [13500,0] [16800,0] [19000,2] [21000,0] [23000,1] [25500,0] [28000,0]`
→ H = 0.4581243533354738, over = 1349.966285628821, T = 1116.5757326445048, 9 полін. `HClicker.kilnRun(…)` у браузері
(headless Chrome) дав **ті самі числа до останнього біта**; у справжній грі (10 натисків через CDP) сервер відкрив горно
з жаром 81 % і перегрівом 31 — рівно те, що намалював клієнт.

Як грається (симуляція гравців, 40 партій кожен): нічого не робити — H = 0; смикати поліно щопів секунди — H = 0 і
тріщини 50 %; рівний ритм «поліно раз на 4 с» наосліп — H ≈ 0,5; уважний палій (реакція 0,3–0,6 с) — H ≈ 0,85–0,9,
тріщин ~1–5 %; неуважний (реакція 1,2 с) — H ≈ 0,7; лінивий (2,5 с) — H ≈ 0,3.

## Якість

```
S = H × (0,6 + 0,4 × краса/100)          (підмайстер: якість 1 завжди)
дзвінкий — 0,3·S²,  добрий — 0,4·S,  решта — звичайний        (кидок Ctx.Rng на кожен виріб, після кидка на тріщину)
```

| Хто палив | E[множник ціни] (1 / 1,6 / 2,6) |
|---|---|
| Підмайстер | ×1,00 |
| Недогріте (H 0,5), без розпису | ×1,13 |
| Уважний палій (H ≈ 0,87), краса 0 | ×1,25 |
| Уважний палій, краса 80 | ×1,50 |
| Ідеальний жар, краса 100 | ×1,72 |

Краса — множник **шансу**, а не ціни. Ідеал для «усе дзвінке» — 30 % на виріб, тож 4 з 4 — ~0,8 % на ідеальну партію
(рідкісна ачівка, як і задумано).

## Розпис: техніки, краса, правдоподібність

Полотно 1000×1000, центр (500; 500). Точки клієнт шле пласким масивом цілих `[dt, x, y, …]` — бо кімната відкидає
payload понад 8 КБ (`Rooms.MaxPayloadBytes`): `dt` — мс від попередньої точки, від'ємне `−(dt+1)` — палець щойно торкнувся
(новий штрих). До 500 точок; клієнт бере зразок не частіше ніж раз на 24 мс і лише з `isTrusted`-подій.

Правдоподібність (`KilnPaint.Implausible`): ≥ 12 точок; тривалість 1,5–30 с; час не назад; якщо ≥ 20 кроків і
std(Δt) < 0,25 мс **і** розкид довжин кроків < 3 % — робот (сама рівність Δt нічого не означає: pointermove у
Chrome вирівняний по кадрах). Плюс: від видачі візерунка мусило минути хоч «тривалість траєкторії − 1 с».

| Техніка | Відкривається | Механіка й краса |
|---|---|---|
| 🌀 Ріжкування | завжди | Коло крутиться (період 4,2–5,6 с, напрям ±). Контур у системі кола `r = r0 + amp·sin(kθ+φ)`; точку переводимо: `θ = кут − dir·2π·мс/період`. 72 дуги; дуга пройдена, якщо точка ближче 28. Краса = 100 × частка дуг × (0,7 + 0,3·точність) × (1 − частка клякс (> 70)) |
| ✒️ Ритування (Косів) | `kosiv` у колекції або 400 обпалених | Той самий слід, але нерухомий контур-розетка `r0 + amp·cos(kθ+φ)`, допуск 18, клякса > 45 важить ×1,5, точність 40 % |
| 🌲 Фляндрування | 10 обпалених | Смуги ангобу y 300–700, 5–7 позначок зі стрілками. Штрих: перетин смуг × рівність (відхилення ≤ 25 — 1, ≥ 90 — 0,3) × напрям (не той — 0,6) × близькість до позначки (≤ 45). Штрих мимо — −8 |
| 💧 Мармурування | 60 обпалених | 4–6 позначок. Краплі (дотик ≤ 400 мс, ≤ 50 руху) до закрутки + закрутка (штрих, що обійшов центр ≥ пів оберта). 60 % — краплі (кожна позначка — найближча до 60), 40 % — закрутка (повний оберт за ≤ 0,9 с), −12 за зайву краплю |
| 🪨 Лощіння (Гавареччина) | `gavarets` у колекції або 150 обпалених | 3–5 вертикальних смуг. Шлях розкладаємо по клітинках 40×40 (кроками ≤ 5, стрибки > 200 не рахуються); клітинка блищить від 100 одиниць шляху (~3 проходи). Краса = частка блискучих у смугах − ½ частки заблищених поза смугами |

Рідна техніка — ритування з косівським розписом, лощіння з гаварецьким — +10 краси. Ідеальна рука (тести) — 80–100 на
кожній техніці, каракулі в кутку — ≤ 15; у браузері справжніми перетягуваннями: ритування 99, фляндрування 100,
мармурування 95, ріжкування 95.

## Вид і збереження

`kiln`: `state, slots, batch[ware], dry, straw, strawPrice, style, tech, beauty, techs[відкриті], pattern {tech, at, shape} | null,
litAt | null, helper, strawOn, seed (лише під час ручного обпалу), coolUntil | null, batches, last {at, helper, heat%, over,

Каталог `catalog.kiln`: тривалості, стелі, **константи моделі** (клієнт бере їх звідси), техніки з описами й умовами.

`KilnRow` — усі поля необов'язкові: `batch, style, tech, beauty, paintSeed, paintAt, litAt, helper, straw, fireSeed,

розпис не з колекції, краса > 100, «палає» без зерна чи без партії — не палає.

## Клієнт

- Вкладка «Горно» (`api.tab(st, 'kiln', 'Горно', 30)`), ярлик показує стан: `Горно · 🔥 0:12` / `♨` / `3/8` / `сухих 4`.
- Велике SVG-горно: камера з виробами (силуети `api.wareSvg`), полум'я в топці росте від дров, світло камери — від жару,
  іскри на кожне поліно, дим із комина, заслінка повертається, солома біля горна, «💨 порив вітру».
- Мінігра жару прямо у вкладці: термометр із зеленою смугою (під час розігріву — лише стеля), стрілка тренду, «у смузі N %»,
  «тріщини N %», «наступне поліно: товсте/тонке», великі кнопки «🪵 Поліно» і «Заслінка» (pointerdown, isTrusted), клавіші ↑/W і ↓/S.
  Таймлайн — у localStorage (`clk.kiln.t`), тож F5 посеред обпалу продовжує гру. Після 30 с + 350 мс горно відкривається
  саме; відмову повторює раз на 2,5 с; поки Око майстра питає — чекає.
- Мінігри розпису — в `api.overlay`: полотно SVG, слід фарби (у ріжкуванні — крутиться разом із колом), лощіння показує
  заблищені клітинки (зелені/червоні), мармурування закручує краплі. Кнопки «Спочатку» (новий візерунок) і «Готово»;
  автоздача: ріжкування — оберт + 1,2 с, фляндрування — стільки штрихів, скільки позначок, мармурування — після закрутки, решта — 14 с.
- Відкриття горна — `api.overlay`: вироби з'являються по одному (дзвінкі сяють і гойдаються, тріснуті розсипаються), підсумок,
  «🔔 Усе горно дзвінке!», кнопка «🧺 В комору» (переходить на вкладку «Комора»). Показується раз (`clk.kiln.seen`), лише
  якщо відкрито не пізніше 10 хв тому; «Останнє горно» у вкладці має «Показати відкриття».
- Хата: `api.layer(st, 'back', 'kiln')` — жар і дим від печі (x ≈ 321, y ≈ 262), поки палає; слабший, поки холоне.
- 375 px без горизонтального скролу; `prefers-reduced-motion` — без анімацій і затримок у події відкриття.
- Звуки `api.sfx`: `kiln-light`, `kiln-roar` (кожні 3 с, поки палає), `stoke`, `damper`, `crack`, `ding`, `open`, `brush`
  (раз на ~260 мс, поки малюєш).

## Баланс

Ціна виробу — `ItemValue` (після перерахунку a6b620d: 0,075–0,12 с пасиву на одиницю роботи). Горно не додає глеків
саме — лише якість (×1,25–1,5 в уважного палія) і пропускну здатність:

- пропускна здатність горна — `місця / ~95 с` (30 с обпалу + 60 с охолодження + завантаження): 6 місць — 0,063 виробу/с,
  24 — 0,25/с. Ліплення на 6 кл/с дає горщиків 0,15/с, левів 0,012/с. На початку (6–8 місць) вузьке місце — горно, і
  це стимул качати піч; у пізній грі (24 місця) — руки;
- пізня гра, 6 кл/с, горщики: 0,15 × 3 с = 0,45 пасиву простими звичайними → уважний палій ×1,5 → 0,68, з розписом ×1,9 →
  ~1,3 пасиву зверху; леви: 0,012 × 60 = 0,72 → ~2 пасиви. Разом із замовленнями купців (B4) — ~2–3, як і ціль контракту;
- підмайстер-палій — рівно ×1 до ціни і без тріщин: хто не хоче грати, втрачає лише третину-половину, а не все;
- солома — 2 ціни простого горщика за партію: для недосвідченого палія (тріщини 5–20 %) окупається вже на 8-місному горні
  з глечиками, для майстра, що не перегріває, — зайва;
- Око майстра: вага відкритого вручну горна 120 (спійманий глек — 150); горно відкривається не частіше ніж раз на ~90 с,
  тож не частішає перевірок помітно, але й бот, що лише палить, зустріне майстра.

## Відомі обмеження

- Модель жару відома клієнтові (так і мусить бути — він її малює), тож скрипт може прорахувати ідеальний таймлайн без гри;
  від цього стереже лише Око майстра на `open` (як і для глеків із полиці). Нагорода — множник шансу якості, не глеки напряму.
- Сервер не шле вид сам: коли підмайстер закінчив, клієнт просить `look`.
- `KilnSlotsBonus` — властивість без збереження: цех має виставляти її в `SyncGuild`/`LoadGuild`.
