# Гончарне коло — стіл на Full HD (16 вересня 2026)

Скарга: на екрані 1920 × 1080 у коло незручно грати. Зміни — **лише клієнт** (`web/games/clicker.css`,
`web/games/clicker.js`, один запит у `clicker-fair.css`). Сервер, правила й баланс не чіпані, тести не правлені.

## 1. Що було (виміряно в браузері, вікно 1920 × 1080, нік із прод-збереженням)

| | |
|---|---|
| Картка стола | 1152 × **2423** px (сторінка — 2703 px, ~2,5 екрана) |
| Ліворуч: сцена | 620 × 775, весь стовпець 1109 px — сам по собі вищий за екран |
| Праворуч: полиця верстатів | 514 px завширшки, **один** стовпець на 2378 px |
| Під сценою | ~1300 × 620 px порожнечі: лівий стовпець закінчився, правий ще ні |

Через це: коло — те, по чому клацають, — ховалося за згином, щойно гравець гортав до верстатів; лічильник, смуга
«Шлях виробу» й кнопка «Далі» теж їхали з екрана; половина ширини не працювала. Двостовпцева полиця в css була, але
за порогом `@container (min-width: 1300px)` — картка з балачками має 1152 px і **ніколи** до нього не дотягувалась.

## 2. Що стало

| | |
|---|---|
| Картка стола | 1152 × **960** px — рівно в екран під шапкою сайту |
| Сцена | 488 × 610 (міряється вільною висотою вікна) |
| Полиця верстатів | 646 px, **два** стовпці, гортається сама в собі |
| Прокрутка сторінки | одна, на вході: `scrollIntoView` ставить стіл під шапку |

## 3. Як зроблено

1. **`--clk-stage-w`** — ширина сцени й ширина стовпця сітки одним числом:
   `clamp(420px, calc((100vh - 470px) * .8), 620px)`. 470 px — те, що з'їдають шапка сайту, рядок стола,
   лічильник, смуга «Шлях виробу» й прилавок; `.8` — сцена 4:5. На екрані 1440 px заввишки й вище сцена
   лишається 620 px, як була; нижче 420 px не тиснемо — краще трохи прокрутити, ніж дивитись у сірник.
2. **`.clk-side { max-height: calc(100vh - 120px) }` + `.clk-pane { overflow-y: auto; min-height: 0 }`** —
   гортається лише полиця верстатів. `overscroll-behavior: contain`: колесо над полицею не тягне сторінку.
3. **`position: sticky; top: 62px`** на обох стовпцях — коли вміст вкладки таки переростає екран, сцена
   лишається на місці.
4. **Іменовані контейнери.** `.clk` → `clk`, `.clk-side` → `clkside`. Двостовпцева полиця тепер міряє **себе**
   (`@container clkside (min-width: 560px)`), а не всю картку. Запит дошки купців у `clicker-fair.css` явно
   прив'язано до `clk` — інакше після появи нового контейнера він читав би полицю.
5. **`placeInView(st)`** у `clicker.js` (перший вид після того, як картка стала видною) — `scrollIntoView` з
   `scroll-margin-top: 62px`. Каркас монтує картку один раз і далі лише ховає її, тому міра — не `mount`.
   Перевірки: лише від 1000 × 700 px; нічого не робимо, якщо картка й так уміщається або гравець уже гортав сам.

## 4. Де нічого не змінилось

- **Телефон і планшет** (до 900 px картки): стовпчик, `position: static`, полиця без власної прокрутки — усе як було.
- **Вікно нижче 700 px** (`@media (max-height: 699px)`): сцена знову 620 px, липкості й прокрутки полиці нема —
  на такому екрані гортати однаково доведеться.
- Сцена, SVG, мінігри, звук, тексти, гейти вкладок — недоторкані.

## 5. Перевірено в браузері

1920 × 1080 із балачками й на весь екран (⛶), 1366 × 768, 375 × 812 (телефон) — нік із прод-збереженням
(усі п'ять вкладок, комора, цех, клейма) і нік-новачок із завісою Ока майстра. На кожній ширині: всі п'ять
вкладок відкриваються, полиця гортається сама, горизонтальної прокрутки нема, вікна (`api.overlay`) видно
цілком, кліки по колу дають «+N» і бризки.
