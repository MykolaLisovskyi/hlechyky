# Своя гра (`svoya`) — специфікація

> Стан: **зроблено всі етапи §8** (19.09.2026, коміти a49b650 … етап 7). Розділи 2–7 — специфікація з
> примітками «Як реалізовано», §8 — журнал етапів, §9 — рішення власника.

Аналог «Своєї гри» (Jeopardy!): поле «теми × вартість», кнопка, кіт у мішку, аукціон, фінал. Ведучий —
автомат із голосом (edge-tts, Остап), а не людина. Пакети запитань: вбудовані (згенеровані AI), свої
(конструктор на сайті) та імпортовані з SIGame (`.siq`).

## 1. Що є в платформі і на що спираємось

- **Каркас ігор** — `docs/games/ARCHITECTURE.md`, `PROTOCOL.md`, `TESTING.md`. Гра = клас `Impl/Svoya.cs`
  + модуль `web/games/svoya.js`/`.css`, реєстрація рефлексією, тести через `RoomHarness`.
- **Зразок party-гри з фазами, таймерами й фоновою підготовкою** — `Impl/Melody.cs` (Loading→Play→Reveal,
  `TickMs=250`, `_until`/`_totalMs` у виді, `PrepareAsync` поза замком, `IMelodySource` як інтерфейс для
  підробки в тестах). «Своя гра» будується за тим самим шаблоном.
- **Зразок власного сховища гри в SQLite** — `Impl/AdContestStore.cs` (свій DDL, `Db.With`), і власних
  ендпоінтів — `AdContestSetup.cs` + `GamesSetup.MapHlechykyGames`.
- **Зразок роздачі файлів за токеном** — `MelodyClips` (`/api/games/melody/<токен>.mp3`).
- **Завантаження звуку з браузера і ffmpeg** — `VoiceService.SaveAsync` (ліміт байтів, `.part` → `.mp3`),
  ffmpeg/ffprobe у `tools/yt-dlp/` (`YtDlp:FfmpegDir`).
- **Нечітке порівняння відповідей** — `MelodyAnswer.Hits` (регістр, розділові, транслітерація, одна помилка
  на 5 літер). Перевикористати для автоперевірки відповідей.
- **Панель поруч із «Профілем»** — `HGames.registerPanel` (зразок `ad-contest.js`, панель «🎙 Реклама»).
  Тут житиме конструктор пакетів.
- **Опції кімнати** (`GameOption`) — статичні, рахуються на старті процесу (`Registry`), тож **список пакетів
  через них не передати**. Пакет обирає господар уже в кімнаті (Act `pack`) — див. §3.1.
- **Акаунти** є (`accounts`, `Auth.NickKey`, роль `admin`); власник пакета — `nick_key`.
- **edge-tts** стоїть на машині (`python -m edge_tts`, v7.2.8), голоси `uk-UA-OstapNeural` / `uk-UA-PolinaNeural`;
  досвід — `data/ads-gen/ads2.py`. У сервері TTS ще немає — з'явиться тут (`TtsService`).
- **Anthropic** у сервері вже є (`DjBrain`, `IAdScriptWriter`, `Ai:ApiKey`/`Ai:Model`) — для «згенерувати тему
  AI» у конструкторі (етап 7, не перша версія).
- `data/*` у `.gitignore`, але окремі файли додано явно (`git ls-files data`): вбудовані пакети кладемо в
  `data/svoya/builtin/*.json` і **додаємо в git через `git add -f`**; медіа й пакети користувачів
  (`data/svoya/media`, база) — не в git.

## 2. Модель пакета

JSON, один об'єкт на пакет, зберігається цілком у SQLite (`svoya_packs.json`), медіа — файлами.

```jsonc
{
  "id": "p_a1b2c3d4",               // 8 hex; вбудовані — "b_<slug>"
  "title": "Україна від А до Я",
  "description": "…",               // необов'язково
  "author": "Влад", "authorKey": "влад",   // вбудовані: "Глечики", authorKey ""
  "public": true,                   // видно всім у списку; інакше лише автору
  "source": "builtin" | "user" | "siq",
  "rounds": [
    { "name": "Перший раунд", "type": "normal",
      "themes": [
        { "name": "Історія",
          "questions": [
            { "price": 100, "type": "normal",          // normal | cat | auction
              "text": "Хто написав «Енеїду»?",         // може бути порожнім, якщо є media
              "media": null | { "kind": "image"|"audio"|"video", "file": "3f9a….jpg", "seconds": 12 },
              "answer": "Іван Котляревський",
              "accept": ["Котляревський"],             // додаткові варіанти, що зараховуються
              "answerMedia": null | { … },              // показати при розкритті
              "comment": "Перша книга сучасною українською"   // ведучий читає після відповіді (необов'язково)
              // для cat: "catPrice": 300 | null (null — той, кому передали, обирає min/max раунду)
            }
          ] }
      ] },
    { "name": "Фінал", "type": "final",
      "themes": [ { "name": "…", "questions": [ { "price": 0, "text": "…", "answer": "…" } ] } ] }   // по 1 запитанню на тему
  ],
  "createdAt": "…", "updatedAt": "…"
}
```

Правила валідності (сервер, `SvoyaPack.Validate()` → список рядків-помилок українською):
- ≥ 1 раунд; у `normal`-раунді ≥ 1 тема, у темі 1–8 запитань, ціни > 0, унікальні в темі; у `final` — ≥ 2 теми по
  одному запитанню; фінал не більше одного і лише останнім.
- У запитання є `text` або `media`; `answer` не порожній. Довжини: назва ≤ 60, текст ≤ 600, відповідь ≤ 120.
- Медіа-файл існує в теці пакета. Загальний розмір медіа пакета ≤ `Svoya:PackMaxMb` (типово 150).

**Як реалізовано (етап 1):** перевірок дві. `SvoyaPack.Check()` — жорсткі межі (довжини, ≤ 10 раундів, ≤ 10 тем,
≤ 8 запитань, ≤ 12 варіантів відповіді, ім'я медіа — лише `хеш.розширення`): без них пакет не зберігається
взагалі (400 зі списком). `SvoyaPack.Validate()` — усе з переліку вище: без цього пакет зберігається **чернеткою**
(`ready = false`), і грати в нього не можна. Інакше автозбереження конструктора не пережило б порожнього
шаблону на 80 запитань. `Normalize()` перед обома прибирає краї, порожні й повторні варіанти, невідомі типи.

**Класичний шаблон** (те, що дає «Новий пакет» за замовчуванням): 3 раунди по 5 тем × 5 запитань, ціни
100–500 / 200–1000 / 300–1500, + фінал на 5 тем. Кількість раундів, тем і запитань автор змінює як хоче;
ціни при додаванні раунду рахуються за формулою `крок × (номер раунду) × (1..5)` (крок 100), але правляться руками.

## 3. Правила гри

**Info:** `Id="svoya"`, `Title="Своя гра"`, `Group=Party`, 1/9 місць, `Start=ByHost`, `Hidden=true`
(відповідь до розкриття бачить лише живий ведучий; свої ставки й відповіді фіналу — лише власник),
`TickMs=250`, `Score=HigherIsBetter`.
Опції в лобі: `host` — ведучий (`auto` автомат / `live` жива людина, типово `auto`), `answer` — секунд на
відповідь після кнопки (10/15/20, типово 15), `buzz` — секунд на кнопку після зачитування (5/10/15, типово 10),
`voice` — голос (`ostap`/`polina`/`none`, типово `ostap`).

### 3.0 Два ведучі

| | `auto` — автомат | `live` — жива людина |
|---|---|---|
| Хто ведучий | сервер | творець кімнати (місце 0), **не грає**, рахунку не має; `MinPlayers=2` |
| Читає запитання | голос edge-tts | сам уголос; на своєму екрані бачить текст, медіа й **правильну відповідь** (лише його вид) |
| Відповідь гравця | друкує на телефоні, перевіряє автомат (§10) | каже вголос; ведучий тисне «✓ Правильно» / «✗ Ні» |
| Кнопка | після голосу, `buzz` секунд | ведучий тисне «Кнопка!» коли дочитав (або автоматично після `media.seconds`, якщо запитання — лише медіа); далі `buzz` секунд або поки ведучий не закриє «Ніхто» |
| Хто відповідає | перший за часом сервера; решта — черга (§3.2 п.5) | те саме: перший за часом сервера, черга з мілісекундами видна всім |
| Апеляція | гравець → господар кімнати | не потрібна: ведучий і так суддя; є «± бали» вручну на будь-якого гравця (виправити помилку) |
| Темп | таймери | таймери йдуть, але ведучий може «Далі» (пропустити розкриття/інтро) і «Пауза» |
| Кіт у мішку | одержувач друкує | одержувач каже, ведучий судить |
| Аукціон | ставки на телефонах | ставки на телефонах; ведучий може «Пас за гравця», якщо той завис |
| Фінал | ставки й відповіді друкують усі | ставки друкують; відповіді **теж друкують** (30 с), ведучий бачить усі й ставить ✓/✗ кожній перед розкриттям |
| Голос | так | вимкнено; тумблером можна ввімкнути, щоб автомат читав за ведучого |

У `live` ведучий бере місце 0 як творець кімнати (так уже робить каркас); у видах і рахунку місце 0
пропускається, чіп місця — «🎙 ведучий». Ведучий вийшов посеред партії → партія завершується без
переможця (рядок «ведучий пішов»). Гравці на телефонах у `live` не мають поля для тексту, лише велика
кнопка (і поля ставок в аукціоні/фіналі).

Дії ведучого (`Act`, лише з місця 0 у `live`): `open` (відкрити кнопку), `verdict {ok}`, `nobody` (закрити
запитання, показати відповідь), `next` (далі), `pause`/`resume`, `adjust {seat, delta}`, `passFor {seat}`,
`finalVerdict {seat, ok}`. Усе інше — ті самі дії, що в `auto`.

**Як реалізовано (етап 2):** ведучий — господар столу на момент старту (`IRoomContext.HostSeat`, не обов'язково
місце 0: господар міг вийти з лобі). У `live` місце ведучого виключене з гравців, рахунку й результату; `MinPlayers`
каркаса лишається 1, а «треба ще хоч одного гравця» каже `CanStart()`. Відповідь живого ведучого не згорає за
таймером (таймер — лише підказка), кнопка сама відкривається лише для запитання, що складається з медіа, або
через 60 с читання. Ведучий може й сам обрати клітинку за обирача. Опція лобі `early` (§9): типово кнопку можна
тиснути й під час читання — хто натиснув, той одразу відповідає.

### 3.1 Вибір пакета
Потрібні два гачки каркаса (етап 2): `Game.ActsInLobby` (Act у лобі доходить до гри) і `Game.CanStart()`.
Кімната в стані `lobby` показує господареві список пакетів (`GET /api/games/svoya/packs`: вбудовані,
публічні, мої) з пошуком; вибір — `Act("pack", { id })`. Решта бачить назву пакета й теми раундів (без
запитань). «Почати» без пакета — помилка «Оберіть пакет». З конструктора кнопка «Грати» створює кімнату й
одразу шле `pack`. При «Ще раз» пакет лишається.

### 3.2 Хід партії (фази у виді `phase`)

Описано для `auto`; у `live` ті самі фази, а відмінності — у таблиці §3.0 (замість голосу — «Кнопка!»
ведучого, замість автоперевірки — `verdict`, замість апеляції — `adjust`).
1. `intro` — голос: «Перший раунд. Теми: …». 1 с на тему, потім `board`.
2. `board` — на полі відкриті клітинки; **обирач** (`chooser`, спершу випадковий; далі — хто останнім
   відповів правильно) тисне клітинку: `Act("pick", { theme, q })`. 30 с на вибір, інакше сервер обирає сам
   найдешевшу відкриту.
3. `reading` — на «телевізорі» текст і медіа, голос читає запитання. Кнопка **закрита**, поки звучить
   голос/медіа (сервер знає тривалість mp3). Для `cat` замість цього → `cat`, для `auction` → `auction`.
4. `buzz` — кнопка відкрита `buzz` секунд. `Act("buzz")`: перший за часом сервера стає `answering`.
   Хто вже помилявся на цьому запитанні — тиснути не може. Ніхто не натиснув → `reveal`.
5. `answering` — той, хто натиснув, має `answer` секунд написати відповідь: `Act("answer", { text })`.
   Перевірка автоматична: `MelodyAnswer.Hits(text, [answer, …accept])` плюс «відповідь міститься в тексті
   гравця» (щоб «Тарас Шевченко» зараховувалось на «Шевченко»). Правильно → `+price`, гравець стає
   обирачем, → `reveal`. Неправильно або час вийшов → `−price`, повертаємось у `buzz` для решти (час на
   кнопку знову повний).

   **Черга й дочитування (19.09.2026):** поки один відповідає, решта може тиснути далі — стає в чергу
   (`presses`, видно всім: «1. Іра 0.30 с 🎤 · 2. Оля 0.42 с»). Помилився → одразу відповідає наступний у
   черзі, хто ще не помилявся й не пішов; черга порожня → `buzz`. Голос запитання **завжди дочитує**: ранній
   натиск його не обриває (клієнт не глушить голос в `answering`, а наступну репліку ставить за ним). Якщо
   помилились, поки голос ще читає, а черга порожня, — назад у `reading` до кінця читання (сервер пам'ятає
   `_readEnd`), репліки «Ні» тоді нема; правильна відповідь під час читання — `reveal` довшає на залишок
   читання, щоб «Правильно…» прозвучало після запитання. Таймер відповіді при цьому йде як завжди.
6. `reveal` — 5 с: правильна відповідь, коментар, `answerMedia`; голос: «Правильно, Оля, плюс триста» /
   «Ні. Правильна відповідь — …». **Апеляція:** у `reveal` гравець, якому не зарахували, тисне
   `Act("appeal")`, а господар кімнати — `Act("judge", { accept: true|false })` (1 клік): зараховано → бали
   перекладаються, а все, що сталося на цьому запитанні **після** тієї відповіді, скасовується (чужий плюс
   знімається, чужі мінуси й прострочки повертаються, їхні апеляції гаснуть) — запитання ж закрилося ще тоді.
   Без рішення за 15 с апеляція згорає. Це єдиний ручний елемент, і він потрібен: автомат
   помиляється на синонімах.
7. Поле порожнє → наступний раунд (`intro`) або `final`, або `done`.

**Кіт у мішку (`cat`).** Голос: «Кіт у мішку!». Обирач мусить передати запитання іншому гравцеві:
`Act("give", { seat })` (15 с, інакше — випадковому, крім себе; якщо гравець один — собі). Ціна: `catPrice`
із пакета, або одержувач обирає між min і max раунду (`Act("catPrice", { max: bool })`). Далі `reading` →
одразу `answering` без кнопки, лише для одержувача. Неправильно → `−price`, `reveal`.

**Аукціон (`auction`).** Голос: «Аукціон!». Початкова ціна — номінал клітинки, торгується обирач і далі
по колу. `Act("bid", { amount })` — більше за поточну (крок ≥ 100... точніше ≥ найменшої ціни раунду),
`Act("pass")`, `Act("allin")` (ва-банк — усі свої бали; перебити можна лише більшим ва-банком). У кого
балів менше за поточну ставку — може лише пас; у кого менше за номінал — не торгується (номінал
дістається обирачу, якщо всі пасують). 15 с на рішення, тайм-аут = пас. Переможець торгів відповідає
сам (`answering`), ± ставка.

**Фінал (`final`).** Беруть участь гравці з балами > 0 (нікого → фінал пропускається). По черзі від
найменшого рахунку кожен викреслює тему (`Act("strike", { theme })`, 15 с, інакше випадкова), поки не
лишиться одна. Далі кожен таємно ставить `Act("bet", { amount })` (1..свій рахунок, 30 с, тайм-аут = 1).
Голос читає запитання, 30 с усім написати `Act("answer", { text })`. Розкриття по одному від найменшого
рахунку: відповідь, ставка, ± ставка. Тоді `done`.

**Як реалізовано (етап 4):** окремий файл `Svoya.Special.cs` (частковий клас). Кіт: фаза `cat` — поки кота не
віддали, запитання не видно нікому; одержувач обирає ціну (`catPrice {max}`), якщо в пакеті її нема; тайм-аути —
випадковий одержувач і найменша ціна; один гравець — кіт дістається йому. Хто відповідає сам (кіт, аукціон), той
у виді як `solo`: кнопки нема, помилка одразу закриває запитання. Аукціон: крок = найменша ціна раунду; ставка,
що дорівнює всім балам гравця, — це ва-банк; ніхто не може підняти (усі бідніші за номінал) — запитання одразу в
обирача за номіналом. Фінал: фази `strike` → `bet` → `final` (запитання + 30 с на відповідь, переписувати можна)
→ у `live` ще `judging` (ведучий ставить ✓/✗ кожному, «Розкрити» — лише коли оцінено всіх) → `finale` (по одному,
від найменшого рахунку, 4 с або скільки звучить репліка). У `auto` фінал розкривається одразу, щойно відповіли всі.
Апеляції у фіналі немає. Фазові імена: `cat`, `auction`, `strike`, `bet`, `final`, `judging`, `finale`.

**Кінець.** Переможці — максимум балів (можна кілька), `Ctx.Score` кожному, `Ctx.Finish` з рядком
«Своя гра: Оля 2300, Петро 1100 — …». Вихід гравця посеред партії — його місце «вимкнене» (як `_left`
у Melody), партія триває.

### 3.3 Вид
Спільний для всіх, крім таємного: `phase, round, roundName, board: [{theme, cells:[{price, open, type?}]}]`
(тип `cat`/`auction` **не** показується до вибору), `chooser`, `question: {text, media, seconds} | null`
(лише з `reading`), `answering`, `until, totalMs`, `answer` (лише в `reveal`/`done`), `scores[]`,
`wrong[]` (хто вже помилявся на цьому запитанні), `auction: {bids, current, turn}`, `final: {themes,
struck, bets: [seat…] лише хто вже поставив}`, `say: { text, url|null, id }` — поточна репліка ведучого,
`me: { bet, answer, canBuzz, canAnswer }`, `left[], result`. Глядач (`seat == null`) — без `me`.
Тест: до `reveal` у виді немає `answer`, у чужому виді немає моїх `bet`/`answer` у фіналі.

## 4. Голос ведучого (`TtsService`)

- Клас `TtsService` (сервер, `src/Hlechyky/TtsService.cs`): `Task<TtsClip?> GetAsync(string voice, string text, ct)`
  → `{ Url, Seconds }`. Кеш на диску `cache/tts/<sha1(voice|text)>.mp3`; є файл — не генерує.
  Генерація: `python -m edge_tts --voice uk-UA-OstapNeural --text "…" --write-media <tmp>` → перейменувати.
  Тривалість — `ffprobe` (є в `tools/yt-dlp`). Черга з одним воркером і тайм-аутом 20 с на репліку;
  провал → `null` (і лог), не виняток. Налаштування `Tts:Enabled`, `Tts:Python` (типово `python`), `Tts:CacheDir`.
- Роздача: `GET /api/games/svoya/tts/<sha1>.mp3` (файл із кешу, `Cache-Control: max-age` довгий — хеш незмінний).
- **Попередня генерація:** при збереженні/імпорті пакета — фонова задача через усі тексти запитань,
  відповідей і коментарів. На старті партії — `PrepareAsync` як у Melody: дочекатись реплік першого раунду,
  решту готувати під час гри; репліка ще не готова, коли вона потрібна → сервер чекає до 5 с, далі йде
  без звуку (`url: null`).
- **Репліки-шаблони** з іменами: «Правильно, {нік}, плюс {ціна}» — теж через кеш (на партію їх десятки,
  на диску — копійки). Числа читаються словами (edge-tts читає «300» нормально, але «плюс триста» краще —
  зробити маленький `NumberWords` для 1..99 999, або залишити цифри; перевірити вухом).
- **Фолбек у браузері:** `say.url == null` → `speechSynthesis` з `lang: 'uk-UA'`, якщо є голос; інакше тиша,
  таймери йдуть від фіксованої оцінки (`text.Length / 14` с).
- **Де звучить:** голос грає на тому пристрої, де увімкнено тумблер «🔊 Ведучий тут». Типово увімкнено у
  глядача (телевізор) і в господаря кімнати, вимкнено в решти гравців (щоб не звучало з восьми телефонів).
  Стан — у `localStorage`. Радіо на час репліки глушиться, як у Melody (`duck`).
- Судити **вухом** (див. пам'ять `audio-judge-by-ear`): швидкість Остапа `-4%…+0%`, паузи після крапки.

**Як реалізовано (етап 3):** `TtsService` (BackgroundService) — черга з одним воркером (`LinkedList`, термінові
репліки — на початок), рушій `ITtsEngine` окремо (`EdgeTtsEngine`: `python -m edge_tts --rate=…`, ffprobe;
у тестах — підробка). Кеш `cache/tts/<sha1(голос|швидкість|текст)>.mp3` + `.sec` із тривалістю, тож після
рестарту нічого не міряється наново. Невдала репліка більше не пробується до рестарту — гра читає її без голосу.
Гра нічого не чекає під замком: `ISvoyaVoice.Ready` лише дивиться в кеш, а репліку, якої ще нема, ставить
терміновою й чекає до 5 с (таймер фази стоїть, у виді `waiting: true`). На старті раунду в чергу йде весь
раунд, на кнопку — обидва вердикти («Правильно, Оля! Плюс сто.» / «Ні. Мінус сто.»), на збереження готового
пакета — увесь пакет (`SvoyaLines.All`). Числа словами — `NumberWords` («тисяча п'ятсот»). Збій голосу гру не
валить. Живий ведучий може ввімкнути голос тумблером (`Act voice {on}`) — тоді кнопка відкривається сама, щойно
голос дочитав. Швидкість — `Tts:Rate` (типово `+0%`, зразки обох швидкостей віддано власнику 19.09).
Клієнт: «🔊 Ведучий тут» (localStorage `svoyaSpeaker`), після F5 стара репліка не повторюється, без
українського голосу `speechSynthesis` мовчить (краще тиша, ніж англійський акцент), радіо глушиться на репліку.

## 5. Медіа

- Завантаження з конструктора: `POST /api/games/svoya/packs/{id}/media` (multipart, одне поле `file`).
  Дозволено: зображення jpg/png/webp/gif ≤ 5 МБ (перевірка сигнатури, зберігаємо як є); звук mp3/ogg/m4a/wav
  ≤ 15 МБ → ffmpeg у mp3 128k, ≤ 90 с (довше — обрізати з попередженням); відео mp4/webm ≤ 60 МБ → ffmpeg
  h264/aac ≤ 720p, ≤ 90 с. Ім'я файла — sha1 вмісту + розширення; тека `data/svoya/media/<packId>/`.
  Відповідь: `{ file, kind, seconds, bytes }` — конструктор кладе в `question.media`.
- Роздача: `GET /api/games/svoya/media/<packId>/<file>` (без списку тек, лише за точним іменем).
  Спойлерів немає: ім'я — хеш, а що в ньому — видно лише тоді, коли вид уже показує це запитання.
- У грі: `reading` показує зображення одразу з текстом; звук/відео грає на «телевізорі» (і в господаря),
  кнопка відкривається після `media.seconds` (або після голосу, що довше). Відео — `<video playsinline muted?>`
  ні, зі звуком; автоплей після кліку користувача можливий, бо сторінка вже мала взаємодію (як Melody).
- Квоти: пакет ≤ `Svoya:PackMaxMb` (150), усі пакети одного ніка ≤ `Svoya:UserMaxMb` (500), адмін — без
  меж. Видалення пакета видаляє теку. Файли, на які пакет більше не посилається, прибирає `Save` (різниця
  списків).

## 6. Конструктор і сховище

**Сховище** `SvoyaStore` (як `AdContestStore`): таблиця
`svoya_packs(id PK, owner_key, owner_nick, title, public, hidden, ready, source, json, media_bytes, created_at, updated_at)`
і `svoya_plays(pack_id PK, n)` — лічильник партій, спільний і для вбудованих (яких у `svoya_packs` нема).
`hidden` ставить адмін (`POST packs/{id}/hide {hidden}`), `ready` — результат `Validate()` на збереженні.
Логіка прав — у `SvoyaPacks` (тестується без HTTP), ендпоінти — у `SvoyaSetup`; відповіді `{ ok, message, data }`
або 400 `{ ok: false, message, errors[] }`.
Вбудовані пакети — з `data/svoya/builtin/*.json`, читаються на старті (як `SkilkyBank`), у списку йдуть
першими з підписом «від Глечиків», редагувати не можна (можна «Скопіювати до себе»).

**API** (усе під `/api/games/svoya/…`, нік — з куки як усюди):
- `GET packs` → `{ builtin: [...], public: [...], mine: [...] }`, у рядку лише `id, title, author, rounds:
  [{name, themes: [назви]}], questions, mediaMb, plays, updatedAt, canEdit` — без запитань (спойлери).
- `GET packs/{id}` — повний JSON; лише автор або адмін (для гри сервер читає сам, не через HTTP).
- `POST packs` — новий (з шаблону або з тіла), `PUT packs/{id}` — зберегти цілком (валідація → 400 зі
  списком помилок), `DELETE packs/{id}`, `POST packs/{id}/copy`, `POST packs/{id}/media` (§5),
  `POST packs/import` (`.siq`, §7), `GET packs/{id}/export` (наш JSON + медіа в zip).
- Право: `owner_key == nick_key` або адмін. Створювати можуть **лише зареєстровані** (рішення власника
  19.09.2026; `Svoya:GuestsCreate` вмикає й гостей); гостю — «Увійди, щоб робити пакети». Гість «гість Оля» —
  інший ключ, ніж «Оля», тож чужого пакета не торкнеться. Ще межа: ≤ `Svoya:MaxPacks` (50) пакетів на ніка.

**Панель** `HGames.registerPanel({ id: 'svoya', title: '🎯 Своя гра' })` у `web/games/svoya-packs.js`
(окремий файл від модуля гри, щоб модуль гри лишався легким; `svoya.js` його не тягне):
- список (три групи, пошук, «Грати», «Редагувати», «Скопіювати», «Видалити», «Імпортувати .siq»,
  «Новий пакет»);
- редактор: шапка (назва, опис, публічний), вкладки раундів (+ раунд, ✕, назва, тип normal/final,
  «перерахувати ціни»), таблиця тем × запитань, клітинка → шухляда: тип, ціна, текст, медіа (завантажити /
  прибрати / прослухати), відповідь, «також приймати» (через `;`), коментар, медіа відповіді;
  «⬆⬇» для порядку тем; «Перевірити» показує помилки валідації; автозбереження через 1,5 с після
  останньої зміни (PUT цілого JSON, індикатор «збережено»); «Озвучити» — примусова прегенерація голосу
  з прогресом (`GET packs/{id}/tts` → `{ ready, total }`).
- Працює на телефоні (одна колонка), але це інструмент для ноутбука.

**Як реалізовано (етап 5):** `SvoyaUploads` (`Impl/SvoyaMedia.cs`) — прийом у теку пакета через тимчасовий
`.up-*.part`, картинка — лише за сигнатурою (jpg/png/gif/webp, розширення з браузера не вірить), звук і відео —
через `ISvoyaTranscoder` (`FfmpegTranscoder`: mp3 128k / h264+aac ≤ 720p, `-t 90`, «Обрізано до 90 с»). Ім'я —
перші 24 знаки sha1 готового вмісту. Квота ніка рахується за фактичними теками всіх його пакетів (там і
завантажене, але ще не збережене); адмін — без меж. `Save` прибирає файли, на які пакет не посилається, але
лише старші за 30 хв (`OrphanGrace`) — щойно завантажений файл інакше зник би від автозбереження, що про нього
ще не знає. Роздача `GET /api/games/svoya/media/{pack}/{name}` з Range і довгим кешем. `POST /api/games/svoya/check`
— «а якщо напишуть…» тим самим `SvoyaAnswer`.
Панель: `svoya.js` реєструє заглушку «🎯 Своя гра» і довантажує `svoya-packs.js`, лише коли панель відкрили
(окремої плитки в лобі не треба, на відміну від `AdContestTile`). Редактор перемальовується лише на структурних
змінах (раунд, тема, клітинка), а на введенні тексту оновлює тільки статус і підпис вибраної клітинки — щоб не
збивати фокус. «Грати» / «Вести самому» — `CreateRoom` + `Act pack` і перехід до столу.

## 7. Імпорт `.siq` (SIGame) і AI-пакети

**.siq** — zip: `content.xml` + теки `Images/`, `Audio/`, `Video/` (імена файлів у xml — URL-кодовані, це
відома пастка). Схема (версії 4 і 5):
`package(name, version) > rounds > round(name, type="final"?) > themes > theme(name) > questions > question(price, type?)`.
v4: `type name="cat"|"bagcat"|"auction"|"sponsored"` з `param`; `scenario > atom(type=text|image|voice|video|marker, time)`;
`right > answer*`, `wrong > answer*`. v5: `params > param name="question" > item(type=…)`, `param name="answer"`,
`param name="theme"/"price"` для кота. Мапа: `bagcat`/`cat` → `cat` (ціна з param або null), `auction` → `auction`,
`sponsored` → `normal`; атоми тексту склеюються в `text`, перший медіа-атом → `media` (решта — у коментар
попередженням), медіа після `marker` → `answerMedia`; `right` → `answer` + `accept`. Медіа проганяється через
ті самі правила §5 (перекодування, ліміти; надто велике — пропускається з рядком у звіті імпорту).
Результат: `{ id, warnings: [...] }`. Більшість публічних пакетів SIGame — російською; переклад — не в
першій версії (можливий етап 7б через Anthropic, по темі за раз, із перевіркою автором).

**Як реалізовано (етап 6):** `SvoyaImport` (`Impl/SvoyaImport.cs`). Формат визначається вмістом: `pack.json` —
наш zip, `content.xml` — SIGame; версія 5 — за наявністю `params` у запитанні. v5: `secret*` → кіт (ціна — коли
`numberSet` має min = max), `stake` → аукціон, решта → звичайне; `param question/answer` з `item` (text / image /
audio / video, `isRef`). Імена в архіві шукаються без регістру й з розкодуванням (кирилиця в SIGame лежить
URL-кодованою). Друге медіа в одному місці й відсутній файл — рядок у звіті. `Fit` підрізає те, що вийшло за
межі `Check` (назви 60, текст 600, відповідь 120, ≤ 10 раундів/тем, ≤ 8 запитань, фінал — одне запитання на
тему й лише один фінал, останнім), і каже, що саме. Імпортований пакет — приватний, власник — той, хто імпортував;
недороблене стає чернеткою з переліком зауважень. `POST packs/import` (multipart `file`, ≤ 250 МБ),
`GET packs/{id}/export` — лише автору чи адміну.

**Експорт** — власний zip (`pack.json` + `media/`), імпорт його ж (щоб пакети переносились між серверами).
Експорт у `.siq` — не робимо.

**AI-пакети для першої версії** пише Claude прямо в сесії (без API) як `data/svoya/builtin/*.json`,
4–6 штук, кожен — класичний шаблон (3 раунди × 5 тем × 5 + фінал 5 тем), українською. Теми на вибір:
«Україна», «Кіно й серіали», «Музика (українська і світова)», «Наука і техніка», «Їжа і напої», «Спорт»,
«Ігри (відео й настільні)», «Дитинство 2000-х». Правила якості — ті самі, що в банку «Скільки?»
(`data/questions/skilky.json`): факти перевірювані, без вигаданих чисел і спірного; складність росте з
ціною; відповідь — одне-два слова, `accept` — очевидні варіанти (прізвище без імені, латиниця). Без медіа
(медіа з інтернету не тягнемо — авторські права і посилання гниють). Кожен пакет перечитати очима перед
комітом; сумнівне — викидати.

Кнопка «Згенерувати тему AI» в конструкторі (через `DjBrain`/`Ai:ApiKey`, 5 запитань на назву теми,
автор редагує) — етап 7б, після всього іншого.

## 10. Автоперевірка відповіді (режим `auto`)

Береться `MelodyAnswer.Hits(text, [answer, …accept])` як є (правила перевірені по коду 19.09.2026):
- регістр, розділові знаки, апострофи, зайві пробіли — не важать;
- **одна помилка на кожні 5 літер** правильної відповіді (Левенштейн), і різниця довжин у тій самій межі:
  «онука» — 1 помилка, «Шевченко» — 1 («Шевченка» проходить), «Котляревський» — 2, «Київ» (4 літери) — 0;
- **більше, ніж треба** — проходить, якщо відповідь є в тексті **цілими словами**: «Тарас Шевченко» ⊇
  «Шевченко», «це Котляревський» теж. Приклеєне без пробілу — ні. Відповіді коротші за 3 літери входженням
  не шукаються;
- **кирилиця ↔ латиниця**: обидва боки зводяться до латиниці зі злиттям схожих звуків, тож «онука» =
  «ONUKA», «Океан Ельзи» = «Okean Elzy», «Скрябін» = «Skryabin».

Додати для «Своєї гри» (`SvoyaAnswer` поверх `MelodyAnswer`):
- **числа**: якщо відповідь — число, у тексті гравця шукається те саме число серед цифр («у 1991 році» ⊇
  «1991»); числа словами (1..99) зводяться до цифр у простих випадках («п'ять» → 5); решту — через `accept`;
- **кілька відповідей** у пакеті: `accept` перебирається всім списком (уже так);
- відмінки далі за одну помилку («Львова» на «Львів») і синоніми автомат не бере — для цього `accept` у
  конструкторі й апеляція господарю (§3.2 п. 6). У конструкторі поруч із полем «також приймати» — кнопка
  «Перевірити» з полем «а якщо напишуть…», щоб автор одразу бачив, що зарахується.

Тести: кожен пункт вище — окремий кейс у `SvoyaAnswerTests`.

## 9. Рішення власника (19.09.2026)

1. Пакети створюють **лише зареєстровані**.
2. Публічні пакети видно **одразу**, адмін може сховати.
3. Назва — **«Своя гра»**.
4. Кнопка під час читання — **опцією лобі** `early`: типово **можна** («натиснув — хай відповідає, може він
   питання швидше прочитав»), друге значення — лише після читання. Блокування за фальстарт не робимо.

## 11. Характер ведучого (19.09.2026)

Ведучий-автомат не лише читає й рахує, а реагує на ситуацію: хвалить, підколює, помічає серії й лідера,
підбиває підсумок. Рішення власника: «хочу, щоб було весело» — один характер на обидва голоси, без
перемикача в лобі, з пам'яттю про партію.

- **Книга фраз** — `data/svoya/host.json` (шлях `Svoya:HostFile`), читається раз на старті
  (`SvoyaPhrases.Load`). Кожен ключ — пул реплік; гра обирає одну навмання, **не ту саму, що минулого разу**
  з цього пулу (`Pick` + пам'ять `_lastPick` на партію). Підстановки: `{nick}`, `{sum}` (словами, `NumberWords`),
  `{answer}`, `{said}`, `{theme}`, `{themes}`, `{round}`, `{nicks}`; що дозволено в якому пулі —
  `SvoyaPhrases.Allowed`. Файла нема, кривий JSON, невідомий пул чи підстановка → лог і **сухий ведучий**
  (`SvoyaPhrases.Plain`: ті самі репліки, що були до характеру; `SvoyaLines` бере їх звідти ж, тож
  озвучене наперед для пакета лишається чинним). Ключі з підкресленням (`_про`) — коментарі автора.
  Нік — завжди в називному відмінку: після прийменників («для», «від») не ставити.
- **Ситуації** (обираються в `ChooseVerdicts` на кнопку, до відповіді, щоб голос устиг):
  правильно — `rightFirst` (перша правильна в партії) › `rightStreak` (третя й далі поспіль у одного) ›
  `rightLead` (вийшов уперед) › `rightBack` (вибрався з мінуса) › `rightBig` (найдорожча ціна раунду) › `right`;
  неправильно — `wrongMinus` (пішов у мінус) › `wrongBig` › `wrong`; `timeout` — час вийшов (у `Wrong`
  без тексту); `wrongLast` — промах, після якого нікому відповідати (кіт, аукціон, останній із гравців):
  «Ні» тоді каже розкриття разом із правильною відповіддю, а не окрема репліка, яку розкриття перекрило б (так було
  до характеру: «Ні» останнього гравця фактично не звучало).
  `nobody` / `nobodyAgain` (друге поспіль без відповіді) обираються ще в `Open`. `cat`, `auction`,
  `finalBets` (`{theme}`), `finalRight`/`finalWrong`/`finalNone` (по фіналісту), `intro` / `introLead`
  (з другого раунду й у фіналі — з єдиним лідером у плюсі). Коментар автора до запитання дочитується після
  `right*`, `wrongLast`, `nobody*`.
- **Підсумок** — `endWin {nick} {sum}` / `endDraw {nicks}` / `endNobody`: обирається й озвучується
  **наперед** (`PrepareEnd`), щойно результат видно: на розкритті останньої клітинки партії без фіналу або на
  початку розкриття фіналу (ставки й вердикти вже відомі — рахунок проєктується). В `Over` рахунок звіряється
  з тим, для якого обирали (апеляція на останньому запитанні змінює переможця) — розійшовся, обирається
  наново й іде без очікування (`wait: false`, тоді браузер читає сам). Партія з помилкою (ведучий пішов) —
  без підсумку. Клієнт: репліку в `done` грає, хоч кімната вже не `playing`.
- **Озвучка наперед**: на старті раунду в чергу йдуть, крім пакета, усі варіанти `intro` для раунду й усі
  репліки без підстановок (`Pure()`: кіт, аукціон, `endNobody`). Репліки з ніком — терміново на кнопку
  (три-чотири на відповідь: так/ні/час/промах), «ніхто» — в `Open`, підсумок — за ≥ 4–5 с до фінішу.
- **Текстом**: після вердикту (`buzz`, `answering`, `reveal`) і на фініші репліка показується під
  «телевізором» (`.svsay`, без дубля запитання й коментаря), щоб і без голосу жарт було видно.
- Тести — `SvoyaHostTests`: книга валідна й у кожному пулі ≥ 3 варіанти; кривий файл → сухий; `Pick` не
  повторюється; перша/серія/лідер/найдорожча/у мінус/час/ніхто двічі; підсумок озвучено наперед і збігається
  з тим, що сказано на фініші; фінал — вступ із лідером, ставки, вердикт, перемога; ніхто в плюсі; нічия.
- Що підкрутити після першої партії з друзями: слова й тон (судити вухом, edge-tts не всі наголоси
  бере), чи не набридає, чи не треба пулу «глибокий мінус» і реплік про останню клітинку раунду.
